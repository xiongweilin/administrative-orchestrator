# M7 — Employee Lifecycle Responsibility

Status: **accepted for the recorded isolated real-staging scope**. M7 is the first Administrative vertical that must carry a
relationship to a qualified end instead of only creating one. It is an engineering
milestone, not a design exercise: employee-offboarding must run through real
intake, authoritative HR facts, effective-time waiting, Kernel-owned external
effects, independent verification, Administrative completion, and explicit
persistent-responsibility discharge.

The canonical scenario is exactly one case kind:

```text
employee-offboarding
```

## Core proposition

```text
Employee departure
!=
delete user
```

The chain M7 must complete:

```text
authoritative termination
→ temporal qualification
→ safety revocation
→ continuity transfer
→ employment finalization
→ independent verification
→ Administrative completion
→ explicit responsibility discharge
```

## Normative distinctions

These distinctions are normative for ADR 0004, domain types, tests, and the
acceptance gates:

```text
Offboarding request                          != authoritative termination
Candidate termination date                   != qualified effective time
Human admission                              != termination truth
Termination approved                         != permission to execute before effective_at
Clock >= effective_at                        != authorization still current
Employee record inactive                     != all access revoked
IAM identity disabled                        != sessions revoked
Identity disabled                            != organizational roles revoked
Role revoked                                 != responsibility/ownership transferred
Delegation ended                             != all delegated authority safely reassigned
Provider success                             != revocation verified
One revocation complete                      != offboarding complete
Security cutoff complete                     != continuity transfer complete
AdministrativeCase completed                 != persistent responsibility discharged
Work completed                               != ResponsibilityDischarged
Human says "done"                            != VerifiedReality
Historical employee relationship             != current employee relationship
Rehire                                       != retry old offboarding
Termination cancellation                     != stale offboarding remains authorized
```

Governance-specific additions (ADR 0004 §governance):

```text
Decision dependency truth                    != expected effect target state
Pre-effect governance basis                  != post-effect completion observation
Expected self-induced reality change         != governance drift
```

## Phase model

Offboarding is not `disable_everything()`. At minimum three obligation classes:

### Phase A — SAFETY_REVOCATION

The former subject must not keep using former organizational authority once the
qualified effective time has passed:

```text
Administrative current roles revoked
Administrative delegations terminated
Administrative external identity bindings expired
IAM identity disabled
IAM active sessions revoked
```

### Phase B — CONTINUITY_TRANSFER

Organization-scoped responsibility must not lose its owner when the holder
leaves. Departing holder → successor, for relationships the policy marks as
transfer-required.

```text
missing successor
-/-> keep departing employee access active
```

Correct behavior: security revocation proceeds, the transfer obligation stays
unresolved, the case stays open, and persistent responsibility stays ACTIVE.

### Phase C — EMPLOYMENT_FINALIZATION

HRIS reflects the post-employment reality (`active=false` plus authoritative
termination status/effective time). HRIS deactivation is one obligation, not the
definition of the whole transaction.

## External reality vs domain-state obligations

Two fulfillment sources exist and must stay distinct:

| Kind | Fulfilled by | Examples |
| --- | --- | --- |
| `EXTERNAL_EFFECT_VERIFIED` | Kernel effect + independent readback | IAM disable, session revoke, HRIS deactivate |
| `DOMAIN_STATE_VERIFIED` | Administrative authoritative domain state | role assignment expired, delegation expired, successor role established, principal deactivated |

Administrative-internal state changes must not be wrapped as fake remote
provider effects. Human attestation is never a material security proof.

## External capabilities (deployment-owned, Kernel-generic)

```text
administrative.iam.identity.disable.v1
administrative.iam.sessions.revoke.v1
administrative.hris.employee.deactivate.v1
```

Agent Kernel sees only typed capability, subject, parameters, expected
postcondition, Administrative grant/evidence, and runtime authorization. Kernel
must never learn "employee resigned", "HR approved termination", "successor
manager", or "offboarding complete".

## Persistent responsibility discharge

```text
Administrative CompletionAssessment satisfied
↓
fresh ResponsibilityAssessment
↓
ResponsibilityDischargeDecision
↓
ResponsibilityLifecycleTransition (ACTIVE → DISCHARGED)
```

Auto-discharge shortcuts are forbidden: the three facts stay separate, a
discharge decision does not itself mutate lifecycle state, and any unresolved
transfer, unknown outcome, stale governance, unverified revocation, or still
current departing authority blocks discharge.

## Gates

Gate A–Q are defined in
`docs/acceptance/M7-staging-acceptance-template.md`: trusted intake, subject
identity, authoritative termination, effective-time wait, wake revalidation,
governance stale, security revocation, IAM disable, session revocation, HRIS
finalization, transfer, missing-successor counterexample, completion,
responsibility discharge, unknown/recovery, restart durability, and
rehire/rebound protection.

## Mandatory counterexamples

1. Request claims termination, HRIS has none → zero physical effects.
2. Termination date changes before T → stale/reopen, zero effects.
3. Missing successor → security revocation proceeds, completion blocked,
   responsibility ACTIVE.
4. Provider outcome unknown → reconciliation, no duplicate effect, no discharge.
5. Session revoke cannot be verified → not complete, not discharged.
6. Old employment lifecycle rebound/rehired → old offboarding cannot execute.

## Migration discipline

rewritten or squashed. M5/M6 semantics and acceptance records are preserved.

## Forbidden implementations

```text
offboarding = delete user
disable identity = offboarding complete
HRIS inactive = offboarding complete
case complete = responsibility discharged
missing successor = keep employee access active
model extraction = termination authority
timer fired = permission to act
email date = effective_at truth
provider 200 = verified
unknown effect = retry
human checkbox = session revoked
Admin direct provider call because disable is idempotent
Kernel understands termination policy
hard delete roles/delegations for cleanliness
re-enable employee as automatic compensation
reuse old offboarding after rehire
```

## Blocker policy

Stop only on a real boundary: required external credential unavailable; a real
provider API cannot supply the needed verification; Kernel lacks a generic
semantic primitive rather than only a public seam; the data model cannot safely
distinguish employment episodes; an external system cannot support durable
request/reconciliation identity. Record the exact counterexample and owner
instead of substituting mocks.

## Closure

M7 is complete only when every mandatory Gate (A–Q), all six counterexamples,
full repository tests, mandatory CI, the recorded real-staging acceptance, the
closure PR, and post-merge main CI pass, followed by an annotated
`m7-accepted-YYYY-MM-DD` tag on the closure SHA.
