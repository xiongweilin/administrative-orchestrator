# M9 — Meeting Commitment Intake & Governed Outbound Communication

M9 extends the trusted perception boundary from documents to meeting
transcripts and adds one narrow outbound channel. It is a closed vertical
slice: transcript text becomes a candidate, an authorized human qualifies
identity and time, policy admits a case, the case creates a persistent
responsibility, and a bounded internal Feishu message is sent and verified
through durable event state.

## Current implementation boundary

- closed interpretation profile: `meeting.commitment.v1`;
- candidate classifications: explicit self commitment, ambiguous commitment,
  aspiration, suggestion, information, assignment to other;
- reusable M6 `SourceArtifact`, `DocumentRepresentation`, and `EvidenceSpan`
  lineage;
- current Feishu identity binding required for speaker resolution;
- offset-aware due-time qualification and human basis for relative dates;
- `meeting-commitment:m9-v1` policy and human confirmation API;
- durable candidate, speaker resolution, commitment, fulfillment attestation,
  communication draft, and communication effect records;
- one confirmation and at most one bounded reminder per commitment version;
- authorized due-time revision and cancellation advance the authority epoch;
  cancelled commitments retain history, stale prepared reminders, and require
  explicit responsibility reassessment rather than implicit discharge;
- metadata-only Administrative communication ledger and separate Gateway HMAC;
- generic Kernel communication capability registration with independent
  Feishu message readback adapter;
- separate case completion and responsibility discharge chain.

## Gate matrix

The M9 acceptance record must contain evidence for gates A–R:

| Gate | Required evidence |
|---|---|
| A | transcript artifact and exact EvidenceSpan lineage |
| B | strict candidate-only model output, including prompt-injection rejection |
| C | zero/multiple identity binding ambiguity blocks admission |
| D | explicit self commitment is the only admitted class |
| E | naive/ambiguous due time blocks or remains human-qualified |
| F | policy, human decision, approval satisfaction, and governance basis |
| G | CommitmentRecord creates persistent responsibility, not Work |
| H | deterministic confirmation metadata and content-addressed body |
| I | separate HMAC transport key and private Gateway listener |
| J | replay of one communication event does not duplicate Feishu send |
| K | lost ACK remains outcome unknown and is not blindly retried |
| L | transport acceptance is not delivery confirmation or human read |
| M | writer and verifier identities are separate |
| N | due timer/reminder is bounded and stale after revision/cancellation |
| O | committer-only authorized fulfillment attestation |
| P | completion does not imply responsibility discharge |
| Q | discharge is assessment → decision → transition |
| R | merged CI, isolated staging, real Feishu transcript, and real outbound evidence |

The recorded state is maintained in
`docs/acceptance/M9-staging-acceptance.md`; the no-secret template is
`docs/acceptance/M9-staging-acceptance-template.md`.

## Explicit non-goals

No audio capture/ASR, calendar integration, email/SMS/Slack/group messaging,
marketing/legal/payment authority, delegated assignment, generic task manager,
or M10 features are admitted by this milestone.
